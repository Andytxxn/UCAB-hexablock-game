# UCAB-hexablock-game
Suite móvil de rompecabezas con cuatro juegos de tablero hexagonal (Hexa Lines, Hexa Merge, Hexa Fit y Hexa Sort) construidos sobre un único motor de juego genérico. Clean Architecture, SOLID y patrones de diseño.

## Getting started

Requires Node.js 24 and npm.

```bash
npm ci              # install dependencies
npx expo start      # run the app (Expo Go or a development build)
npm test            # run all test suites
npm run typecheck   # TypeScript check
npx expo lint       # lint, including Prettier formatting
npm run format      # format the code with Prettier
```

Formatting rules live in `.prettierrc.json`. VS Code formats on save once the recommended extensions in
`.vscode/extensions.json` are installed.

## Architecture

The app follows **Clean Architecture** (Robert C. Martin). The code is organised in concentric rings and
**source-code dependencies point inward only**: an inner ring never imports anything from an outer ring.

| Clean Architecture ring | Folder in `src/` | Contents |
|---|---|---|
| Entities | `domain/` | Generic game engine and the rules of each variant. Plain TypeScript. |
| Use cases | `application/` | Generic use cases, parameterised by variant, and the ports they use. |
| Interface adapters | `presentation/`, `infrastructure/` | React Native UI on one side; SQLite, HTTP, level files and audio on the other. |
| Frameworks & drivers | `main/`, `app/` | Composition root that wires everything together, and the expo-router routes. |

```
presentation ─┐
infrastructure ┼──►  application  ──►  domain
main, app ────┘
```

- `domain/` and `application/` are framework-free: no React, React Native, Expo, Drizzle or i18next imports.
- `presentation/` and `infrastructure/` sit in the same ring. By convention they do not import each other: they
  meet through the ports in `application/`, wired in `main/`. The architecture test does not check this yet.
- The rule is enforced by an architecture test, `tests/architecture/dependency-rule.test.ts`, which scans every
  file in `src/` and fails on any outward import or any framework import in the two inner rings.

### Ports

`application/ports/` follows the ports-and-adapters split:

- `ports/in/` — **driving** (primary) ports: the interfaces the use cases expose to the outside. The UI calls
  them.
- `ports/out/` — **driven** (secondary) ports: the interfaces the use cases need from the outside, such as
  repositories, the level source, the API client, the clock and the random generator. `infrastructure/`
  implements them.

## Project structure

```
UCAB-hexablock-game/
├── src/
│   ├── app/                    # Frameworks & drivers — expo-router routes only, thin files that mount screens
│   ├── domain/                 # Entities
│   │   ├── engine/             #   HexBoard<TCell>, GameEngine, IGameRules, IPieceSource, IScoringPolicy,
│   │   │                       #   hex coordinates, IVariantFactory (Abstract Factory)
│   │   └── variants/           #   one folder per variant, each implementing the engine interfaces
│   │       ├── hexa-lines/
│   │       ├── hexa-fit/
│   │       ├── hexa-sort/
│   │       └── hexa-merge/
│   ├── application/            # Use cases
│   │   ├── use-cases/          #   generic use cases (start match, play move, save progress, load level...)
│   │   ├── ports/
│   │   │   ├── in/             #   driving ports
│   │   │   └── out/            #   driven ports
│   │   └── aspects/            #   AOP: decorators/proxies (logging, caching, timing) over the use cases
│   ├── infrastructure/         # Interface adapters — driven side
│   │   ├── persistence/        #   Drizzle schema, SQLite and in-memory repositories
│   │   ├── levels/             #   loads level files from assets/levels and validates them with zod
│   │   ├── api/                #   HTTP client for UCAB-hexablock-api
│   │   └── audio/              #   expo-audio adapter
│   ├── presentation/           # Interface adapters — driving side
│   │   ├── screens/            #   shared screens, no conditionals on the variant
│   │   ├── components/         #   hex board (react-native-svg), pieces, buttons
│   │   ├── hooks/              #   bridge between the use cases and React
│   │   ├── i18n/               #   i18next setup and locales/ (es, en)
│   │   └── theme/
│   └── main/                   # Frameworks & drivers — composition root: variant registry and dependency wiring
├── assets/
│   └── levels/                 # level configuration files: hexa-fit/ (15+), hexa-sort/ (10+)
├── drizzle/                    # SQL migrations generated by drizzle-kit
├── tests/
│   ├── architecture/           # dependency-rule test
│   ├── integration/            # use cases with real repositories on in-memory storage
│   └── contract/               # Pact consumer tests
├── pacts/                      # generated contract, verified by UCAB-hexablock-api
└── docs/
```

Unit tests live next to the code they test (`*.test.ts`). Adding a fifth variant means adding a folder under
`domain/variants/` with its factory and registering it in `main/`; no other layer changes.
